Read the map with the source data

This independent map compares saved Airbnb listing information with Nashville short-term rental permit records and parcel geometry. It is a research aid; it does not establish whether a property is operating illegally.

Occupancy

The estimated capacity is min(2 × bedrooms + 4, 12). Three bedrooms allows 10 guests; six bedrooms allows 12. Marker numbers show advertised guests and, when above capacity, a second line such as “+4”.

Nashville's rule uses permitted sleeping rooms. The map uses advertised bedrooms, which are not independently verified permitted sleeping rooms. This is a screening estimate. If bedrooms are missing, capacity is unknown; a listing above the absolute 12-person ceiling is still flagged for at least that excess. Missing guest counts are unknown, not zero.

Privacy radii and green parcels

Blue circles show the privacy radius saved with each Airbnb location. A missing radius is left unknown; no radius is invented. These circles indicate approximate location information, not surveyed boundaries. Green parcel polygons have at least one permit record with source status ISSUED and no past expiration date at build time. A permit for one unit does not authorize every unit or listing on that parcel. Overlapping a green parcel is a possible geographic relationship, not a confirmed match.

Permit-centered coverage rings are off by default and live under Advanced filters. These optional rings use the adjustable radius around current permit points. “Outside coverage” is a distance filter, not an unlicensed classification. Permit coverage is independent of the saved Airbnb privacy radius. All supplied listing locations remain available, including places outside Nashville; Nashville rules may not apply outside its jurisdiction.

Parcel-overlap warnings and privacy leeway

The privacy-radius slider adds 0–10% to each saved Airbnb radius (default +10%). A saved radius of zero stays zero. ⚠️ and the “likely unlicensed locations” filter mean the adjusted circle does not touch any green current-permit parcel within the selected analysis area. Distance is measured to actual polygon edges, including holes and multipart geometry, in a local metric projection (EPSG:26916). A missing radius or missing parcel data stays unknown. This screening flag is separate from direct permit-number status and is not a legal finding.

Area outline and edge buffer

The outlined area is U.S. Census TIGERweb Davidson County, January 1, 2026 vintage. It includes satellite municipalities; the map does not assert that every jurisdiction has identical STR rules. The signed buffer expands the analysis area when positive and trims its inside edge when negative. A purple dashed line shows this buffer. Warnings and count comparisons always use the selected area, even if you choose to display outside listings.

Listings minus licenses

The difference map counts each listing location and each current permit record once in a fixed 500 × 500 metre grid. Red means listings exceed permit records; green means permit records exceed listings. Click a cell for its two counts and signed difference. The likely-unlicensed heatmap uses only positive differences, weighted by the excess listing count. It does not simply count all listing dots or count repeated overlaps of privacy circles.

Comparisons use all records in the selected analysis area, regardless of listing, host or amenity display filters. Adjusting the edge buffer changes the comparison area; privacy leeway changes parcel-overlap warnings but does not change grid counts. Cells may straddle the boundary; only records whose source points are in the analysis area count. Approximate Airbnb coordinates can shift a listing between cells. Several current permit records may exist at one property. A positive difference does not identify which listings are unlicensed.

Permit numbers and status

A direct match requires an extracted listing permit number equal to a real number in the permit data. All matched records appear in the popup, including expired, cancelled, revoked and other statuses. Matching a number identifies a reference to a permit, not independent verification that the listing occupies that address.

Expired matches are yellow, including expired listings above estimated capacity. Above-capacity listings also have a red border and a “+N” label. When multiple permits match, a current record takes color precedence; every record and its source status remains in the card. ISSUED records with an expiration date before the build date are displayed as expired, with the source status retained. Other source statuses are not silently reclassified as current.

The supplied export currently contains addresses in its “Permit #” field. These are not usable permit identifiers. Extracted numbers remain visible as unmatched until authoritative numbers are supplied. No status is inferred from the nearest parcel or a matching owner name.

Party house finder

🥳 marks listings with any selected amenity keyword category: 🩱 pool (excluding “pool table”), 👙 hot tub / hottub / jacuzzi, 🍻 the whole word “bar”, and 🎱 pool table, and 🎤 karaoke anywhere in listing text. Filters can require any or all selected categories and a minimum number of guests over estimated capacity. Symbols surround the marker when enabled. Keyword evidence is shown in the popup. Negations and references to nearby amenities can still match; these indicators do not prove parties, rule violations, or on-site amenities.

Refresh and downloads

The Python watcher scans saved metadata and details text as files arrive. It does not fetch live Airbnb pages or perform OCR on listing photographs. Listings without saved text remain in the inventory and are reported separately. Source files stay unchanged; repairs and evidence are written to generated outputs.
